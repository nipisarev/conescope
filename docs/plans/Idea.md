Idea of integration and notifications for parallel Claude instances

General concept

Create a special skill for Claude that will allow it to interact with other parallel running instances. This will make it possible to combine work on different projects through a common protocol, and also receive notifications about arising questions on mobile devices.

• Add the ability for one Claude instance to define tasks and coordinate the work of multiple repositories.
• Provide a single management interface for all connected projects, so there is no need to switch between different instances.
• Add the ability to configure notifications that will be sent to a smartphone or smart watch.
• Set up notification integration so the user can receive information about arising questions and changes in projects without being directly at the computer.

It should not be only orchestration for splitting one task across several agents for related projects (like a microservice architecture example). It is also a way to control processes over different tasks in different projects at different stages of work.

The problem I face is the difficulty of switching between similar editor windows like VSCode or Zed. It is easy to confuse the project and answer the asked question wrongly, or write something completely wrong in another project, which breaks the overall chat context and affects the work result, sometimes it is very critical.

I would like to have a single input/output interface to manage all incoming tasks, but in a way that I get the right context, a very clear view of which project it is about, and the ability to see changed files, without mixing them into one pile. A good analogy is like I am the director of a large production group, and other managers come to me with questions, and by looking at the provided data I can solve their question, instead of running around and checking each factory separately (yes, that is also possible, but it just takes a lot of time).
